# Mamla Linux

Нативный Rust-клиент: GTK4, GStreamer WebRTC/Opus, прямой ввод/вывод через PipeWire.
Использует протокол Go-сервера из корня проекта, общий с браузерным клиентом.
Это отдельное окно, без браузера или WebView.

## Сборка

Нужен Rust 1.85+ (Cargo выбирает совместимые зависимости), GTK 4.6+, GStreamer 1.20+
и работающая пользовательская PipeWire-сессия с WirePlumber.

После установки зависимостей можно собрать клиент из корня проекта на Linux:

```sh
make client
./dist/mamla-client
```

Цель собирает release-версию для архитектуры текущего Linux-хоста и копирует её
в `dist/mamla-client`. Путь можно изменить: `make client CLIENT_OUTPUT=./mamla-client`.
В отличие от Go-сервера, этот бинарник динамический: GTK4, GStreamer и PipeWire-плагины
должны быть установлены и на машине запуска. Кросс-компиляция с macOS этой целью
не предусмотрена. Для сборки через Make нужен пакет `make`.

Debian 13 / Ubuntu 24.04 (Rust установите отдельно, если системный старее 1.85):

```sh
sudo apt install build-essential pkg-config libgtk-4-dev \
  libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
  libgstreamer-plugins-bad1.0-dev \
  gstreamer1.0-tools gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
  gstreamer1.0-plugins-bad gstreamer1.0-nice gstreamer1.0-pipewire libsecret-tools
cd linux-client
cargo run --locked
```

Fedora 45 (обычная система с DNF):

```sh
sudo dnf install rust cargo gcc make pkgconf-pkg-config gtk4-devel \
  gstreamer1-devel gstreamer1-plugins-base-devel \
  gstreamer1-plugins-bad-free-devel \
  gstreamer1-plugins-base gstreamer1-plugins-good gstreamer1-plugins-bad-free \
  libnice-gstreamer1 pipewire pipewire-gstreamer wireplumber libsecret

# Из корня скопированного проекта:
make client
./dist/mamla-client
```

`pipewire-gstreamer` предоставляет `pipewiresrc` / `pipewiresink`,
`libnice-gstreamer1` — ICE-плагины, а `gstreamer1-plugins-bad-free-devel` —
библиотеку разработки WebRTC. Для используемого Opus достаточно пакетов Fedora;
RPM Fusion для этого клиента не требуется.

Проверить библиотеки и плагины перед запуском:

```sh
rustc --version
pkg-config --modversion gtk4 gstreamer-1.0 gstreamer-sdp-1.0 gstreamer-webrtc-1.0
gst-inspect-1.0 pipewiresrc
gst-inspect-1.0 pipewiresink
gst-inspect-1.0 webrtcbin
gst-inspect-1.0 nicesrc
wpctl status
```

Запускайте клиент из графической Wayland-сессии обычного пользователя.
GTK4 самостоятельно выбирает оконный backend; отдельной реализации X11 в клиенте
нет. XWayland для работы под Wayland не нужен. Если требуется явно выбрать backend:

```sh
GDK_BACKEND=wayland ./dist/mamla-client
```

Названия пакетов сверены с каталогом Fedora 45:
[PipeWire](https://packages.fedoraproject.org/pkgs/pipewire/pipewire-gstreamer/fedora-45.html),
[libnice](https://packages.fedoraproject.org/pkgs/libnice/libnice-gstreamer1/fedora-45.html),
[WebRTC devel](https://packages.fedoraproject.org/pkgs/gstreamer1-plugins-bad-free/gstreamer1-plugins-bad-free-devel/fedora-45.html).
Сборка именно на Fedora 45 пока не проверялась.

Arch Linux:

```sh
sudo pacman -S --needed rust base-devel pkgconf gtk4 gstreamer gst-plugins-base \
  gst-plugins-good gst-plugins-bad libnice pipewire wireplumber libsecret
cd linux-client
cargo run --locked
```

Не запускайте GUI через `sudo`: PipeWire использует сокет вашей пользовательской сессии.
Оптимизированный бинарник можно собрать командой `cargo build --release --locked`.
Для диагностики плагинов: `gst-inspect-1.0 pipewiresrc`, `gst-inspect-1.0 pipewiresink`,
`gst-inspect-1.0 webrtcbin` и `wpctl status`. Окно само покажет отсутствие нужных плагинов.

## Подключение

Если сервер требует доступ, сначала примите [приглашение в браузере](../AUTH.md),
сохраните личный ключ и один раз введите его в поле «Личный ключ доступа»
или импортируйте скачанный файл кнопкой «Импортировать ключ из файла…».
На открытом локальном POC поле можно оставить пустым.

Имя для сервера с авторизацией берётся из приглашения; вводить его не требуется.
Последние 20 успешных подключений доступны в списке над адресом сервера.
Настройки содержат только адреса и комнаты: `~/.config/mamla/connections.json`
(или `$XDG_CONFIG_HOME/mamla/connections.json`), права файла — `0600`.

Флажок «Сохранять ключ в системном хранилище» по умолчанию включён. Для него нужны
`secret-tool` (пакет Fedora/Arch `libsecret`, Debian/Ubuntu `libsecret-tools`) и
работающий, разблокированный Secret Service, например GNOME Keyring. После успешного
входа ключ сохраняется отдельно от истории, по origin сервера (схема, домен и порт).
При выборе сохранённого подключения ключ подставляется в фоне. Если хранилище
недоступно, появится предупреждение: ключ останется в памяти окна без записи
в обычные файлы. Выключение флажка не удаляет ранее сохранённые ключи; удаляйте их
в менеджере системного хранилища. Для другого устройства импортируйте тот же файл
ключа; файл истории не служит резервной копией доступа.

1. Запустите Go-сервер на доступном адресе. Например на отдельной машине в LAN:
   `ADDR=0.0.0.0:8080 go run .`.
2. В клиенте укажите сервер `http://192.168.0.235:8080`, ID комнаты `local-test`
   и своё имя (только в открытом режиме). Остальные вводят тот же сервер и ID комнаты.
3. Нажмите «Войти». В окне появятся участники и состояния WebRTC-соединений.
   Кнопка микрофона выключает отправку звука во все соединения.
4. «Выйти» останавливает все аудиопайплайны, освобождает PipeWire-устройства
   и закрывает сессию на сервере. Закрытие окна также закрывает сетевые соединения.

Нативному клиенту HTTPS для доступа к микрофону не требуется. Обычный HTTP
подходит для доверенной локальной сети; сигналинг и токены сессии при этом не
шифруются. Для внешней сети используйте HTTPS. Само WebRTC-аудио зашифровано
DTLS-SRTP и при HTTP-сигналинге, но проверка подлинности соединения зависит от сигналинга.

Если хотите разговаривать с браузерными клиентами на других устройствах, сервер
должен быть доступен по HTTPS — из-за браузерного ограничения микрофона.

Для HTTPS с самоподписанным сертификатом есть два способа подключения:

- Обычная кнопка **«Войти»** проверяет TLS. Скопируйте на Linux **только публичный**
  `cert.pem` и укажите его путь в «Устройства и сертификат». Закрытый `key.pem`
  остаётся на сервере. Сертификат должен покрывать IP/домен сервера и быть действующим.
- Для теста в доверенной локальной сети можно раскрыть **«Устройства и сертификат»**
  и нажать **«Войти без проверки TLS»**. Достаточно указать HTTPS-адрес сервера
  (например `https://192.168.0.200:8443`), комнату и имя; PEM-файл не нужен.
  В этом режиме не проверяются доверие сертификату и имя сервера, поэтому возможна
  подмена сервера. Предупреждение остаётся видно во время звонка.

Обход проверки действует только для этого подключения, не сохраняется и не меняет
системное хранилище сертификатов. Перенаправления сервера в этом режиме запрещены.
Следующее подключение обычной кнопкой снова проверяет TLS. WebRTC-медиатрафик
остаётся зашифрованным, но без доверенного сигналинга нет надёжной проверки собеседника.

## Noise gate

Под кнопкой микрофона включите **«Noise gate — отсекать тихий фон»** и выставьте
**порог в дБFS**. По умолчанию gate выключен, начальный порог — −45 дБFS,
диапазон −80…−10. Изменения применяются сразу ко всем собеседникам, без переподключения.

Начните с −45 дБFS и поднимайте порог, пока тихий фон не пропадёт. Например, −30
отсекает больше звуков, чем −60, но может обрезать тихую речь. Порог измеряется
относительно цифрового уровня микрофона, а не в акустических дБ SPL.

Gate анализирует 5-мс RMS-окно до Opus-кодирования. Открытие занимает 5 мс,
удержание — 150 мс, закрытие — 50 мс; гистерезис 3 дБ уменьшает переключения
около порога. Это помогает сохранить короткие паузы в речи и избежать щелчков.
Opus DTX уменьшает трафик тишины; служебные WebRTC-пакеты продолжают передаваться.

Gate глушит тихий сигнал целиком: во время речи он не удаляет фоновый шум,
не заменяет шумоподавление или эхоподавление. Настройки сохраняются на время
работы окна, но не между запусками. Отдельная кнопка mute по-прежнему выключает
микрофон независимо от gate.

## PipeWire

По умолчанию используются системные микрофон и устройство воспроизведения.
В «Устройства и сертификат» можно задать `node.name`, `object.serial` или ID
конкретного узла (поддержка зависит от версии PipeWire). Посмотрите их через
`wpctl status` / `wpctl inspect ID`. Современный плагин использует `target-object`;
на старом доступен `path` (для него используйте числовой ID).

Маршруты можно изменить в qpwgraph/Helvum или системных настройках PipeWire.
Для простоты POC создаёт отдельный capture/playback-пайплайн на каждого собеседника.
При выходе все они переводятся в NULL и уничтожаются.

## P2P и ограничения

Групповой P2P здесь — полный mesh. В комнате из N участников у каждого N−1
WebRTC-соединений. Например, четыре человека — три исходящих потока на человека,
шесть соединений на всю комнату. Это нормально для небольшой группы; текущий
сервер ограничивает комнату шестью людьми. При больших группах выгоднее SFU:
клиент отправляет один поток серверу, а тот пересылает его остальным.

Go-сервер нужен для списка участников и обмена SDP/ICE, а не для обработки голоса.
Без общего сигналинга тоже можно соединиться (вручную обменять SDP/ICE, сделать
локальное обнаружение), но это отдельный механизм; в этом POC сервер требуется
на всё время звонка. Если NAT не пропускает прямое соединение, нужен TURN:
он пересылает зашифрованные медиапакеты. ICE-настройки клиент получает с сервера.

Это первый POC: нет AEC/шумоподавления в нативном аудиопайплайне, выбора устройств
из выпадающего списка, push-to-talk, автоматического восстановления, упаковки
в deb/AppImage и сохранения настроек аудио между запусками. Используйте наушники, чтобы избежать эха.
Выключение микрофона глушит аудио до Opus-кодирования; устройство остаётся открытым
до выхода из комнаты. В пустой комнате capture-пайплайн ещё не создаётся.

## Проверки

```sh
cargo fmt --check
cargo test
# Открыть и закрыть GTK-окно в текущей графической Wayland-сессии:
GDK_BACKEND=wayland cargo run --locked -- --smoke-test
# Отдельно, при запущенном Go-сервере с ICE_SERVERS='[]':
MAMLA_TEST_SERVER=http://127.0.0.1:8080 cargo test three_clients_join_mute_and_leave -- --ignored
```

Ранее проверено в Linux ARM64-контейнере: сборка, обычные тесты,
отдельный интеграционный тест трёх клиентов через Go-сервер (join, mesh-соединения,
mute, leave). Запуск/закрытие GTK-окна ранее проверялся под Xvfb;
проверка окна в Wayland-сессии остаётся для реального Linux-хоста.

Тест WebRTC передаёт синтетический звук в обе стороны между двумя настоящими
GStreamer webrtcbin и проверяет, что он дошёл до декодера. Он не использует микрофон,
PipeWire или интернет. Реальное аудио через PipeWire, Wayland и совместимость
с браузером нужно дополнительно проверить на рабочих Linux-устройствах.
